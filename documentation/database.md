# 🗄️ Database Schema & Security (RLS)

This chapter provides a detailed reference of the PostgreSQL database schemas, constraints, and Row-Level Security (RLS) policies implemented on Supabase.

---

## 🔑 1. Security Architecture & RLS Model

The database enforces a **Zero-Trust Access Model**. Since clients query the database directly via Supabase's PostgREST API, frontend authentication tokens (JWTs) are analyzed at the SQL query execution step to restrict row access.

### Role Syncing Mechanism
When an admin updates a user's role in the `public.profiles` table:
1. A trigger (`trigger_sync_profile_role_to_auth`) calls the function `sync_profile_role_to_auth()`.
2. This script writes the updated role mapping into `auth.users.raw_app_meta_data.role`.
3. Subsequent JWT tokens generated by Supabase Auth contain this claims object, allowing subquery-free security checks using:
   ```sql
   coalesce(auth.jwt() -> 'app_metadata' ->> 'role', 'student') = 'devcom_head'
   ```

## 📋 2. Table Schemas Reference

### Table: `profiles`
Stores core user details for authenticated accounts.
* **Columns**:
  * `id` (`UUID`, Primary Key) $\rightarrow$ References `auth.users(id)` ON DELETE CASCADE
  * `email` (`TEXT`, Not Null, Unique)
  * `full_name` (`TEXT`, Nullable)
  * `avatar_url` (`TEXT`, Nullable)
  * `student_number` (`TEXT`, Nullable)
  * `year_level` (`INTEGER`, Nullable)
  * `program` (`TEXT`, Nullable)
  * `section` (`TEXT`, Nullable)
  * `role` (`UserRole` enum: `'student'`, `'officer'`, `'comm_content'`, `'comm_registration'`, `'comm_photobooth'`, `'devcom_head'`)
  * `position` (`TEXT`, Nullable)
  * `committee_id` (`UUID`, Nullable) $\rightarrow$ References `committees(id)` ON DELETE SET NULL
  * `profile_complete` (`BOOLEAN`, Default `false`)
  * `banned` (`BOOLEAN`, Default `false`)
  * `banned_until` (`TIMESTAMPTZ`, Nullable)
  * `created_at` (`TIMESTAMPTZ`, Default `now()`)
* **Constraints**:
  * `check_profile_email_domain`: Enforces email domains ending with `@umak.edu.ph` (excepting explicit developer accounts like `ggiojoshua2006@gmail.com`).
  * `check_profile_section`: Enforces uppercase alphanumeric naming convention (e.g. `ACSAD`, `A-APPDEV`).
* **RLS Policies**:
  * `Profiles are readable by everyone` $\rightarrow$ `SELECT` for authenticated users.
  * `Users can edit their own profile` $\rightarrow$ `UPDATE` where `auth.uid() = id`.
  * `DevCom Head has full write permissions` $\rightarrow$ `ALL` where role is `'devcom_head'`.

### Table: `committees`
Council sub-organizations (e.g. Logistics, Technical, Finance).
* **Columns**:
  * `id` (`UUID`, Primary Key, Default `gen_random_uuid()`)
  * `name` (`TEXT`, Not Null)
  * `slug` (`TEXT`, Unique)
  * `description` (`TEXT`, Nullable)
  * `head_name` (`TEXT`, Nullable)
  * `icon` (`TEXT`, Nullable)
  * `responsibilities` (`TEXT[]`, Default `{}`)
  * `display_order` (`INTEGER`, Default `0`)
  * `created_at` (`TIMESTAMPTZ`, Default `now()`)
* **RLS Policies**:
  * `Committees readable by everyone` $\rightarrow$ `SELECT` for public.
  * `DevCom Head write access` $\rightarrow$ `INSERT/UPDATE/DELETE` for `'devcom_head'`.

  * `name` (`TEXT`, Not Null)
  * `position` (`TEXT`, Not Null)
  * `committee_id` (`UUID`, Nullable) $\rightarrow$ References `committees(id)` ON DELETE SET NULL
  * `photo_url` (`TEXT`, Nullable)
  * `email` (`TEXT`, Nullable)
  * `display_order` (`INTEGER`, Default `0`)
  * `term` (`TEXT`, Default `'2026-2027'`)
  * `created_at` (`TIMESTAMPTZ`, Default `now()`)
* **RLS Policies**:
  * `Officers readable by everyone` $\rightarrow$ `SELECT` for public.
  * `DevCom Head write access` $\rightarrow$ `INSERT/UPDATE/DELETE` for `'devcom_head'`.

### Table: `events`
Upcoming council and academic roadmap milestones.
* **Columns**:
  * `id` (`UUID`, Primary Key)
  * `title` (`TEXT`, Not Null)
  * `description` (`TEXT`, Nullable)
  * `category` (`'general' | 'priority'`, Default `'general'`)
  * `event_date` (`DATE`, Not Null)
  * `event_time` (`TEXT`, Nullable)
  * `location` (`TEXT`, Nullable)
  * `registration_required` (`BOOLEAN`, Default `true`)
  * `registration_cap` (`INTEGER`, Nullable)
  * `created_by` (`UUID`) $\rightarrow$ References `profiles(id)` ON DELETE SET NULL
  * `created_at` (`TIMESTAMPTZ`, Default `now()`)
* **RLS Policies**:
  * `Events readable by everyone` $\rightarrow$ `SELECT` for public.
  * `Admins write access` $\rightarrow$ `ALL` for `'devcom_head'` or `'comm_content'`.

---

### Table: `event_registrations`
Contains student bookings for events. Protected by capacity gates.
* **Columns**:
  * `id` (`UUID`, Primary Key, Default `gen_random_uuid()`)
  * `event_id` (`UUID`, Not Null) $\rightarrow$ References `events(id)` ON DELETE CASCADE
  * `profile_id` (`UUID`, Not Null) $\rightarrow$ References `profiles(id)` ON DELETE CASCADE
  * `status` (`'confirmed' | 'pending' | 'cancelled' | 'attended'`, Default `'confirmed'`)
  * `registered_at` (`TIMESTAMPTZ`, Default `now()`)
* **Constraints**:
  * `unique_event_profile`: Restricts double booking of a single event by the same user.
* **RLS Policies**:
  * `Users can view their own registrations` $\rightarrow$ `SELECT` where `auth.uid() = profile_id`.
  * `Admins can manage registrations` $\rightarrow$ `ALL` for `'devcom_head'` or `'comm_registration'`.

---

### Table: `conversations` & `messages`
Support desk chat pipelines.
* **Conversations Columns**:
  * `id` (`UUID`, Primary Key, Default `gen_random_uuid()`)
  * `profile_id` (`UUID`, Unique) $\rightarrow$ References `profiles(id)` ON DELETE CASCADE
  * `created_at` (`TIMESTAMPTZ`)
  * `last_message_at` (`TIMESTAMPTZ`)
* **Messages Columns**:
  * `id` (`UUID`, Primary Key, Default `gen_random_uuid()`)
  * `conversation_id` (`UUID`) $\rightarrow$ References `conversations(id)` ON DELETE CASCADE
  * `sender_id` (`UUID`) $\rightarrow$ References `profiles(id)` ON DELETE CASCADE
  * `student_id` (`UUID`) $\rightarrow$ References `profiles(id)` ON DELETE CASCADE
  * `sender_role` (`'student' | 'admin'`)
  * `content` (`TEXT`, Not Null)
  * `read_by_student` (`BOOLEAN`, Default `false`)
  * `read_by_admin` (`BOOLEAN`, Default `false`)
  * `created_at` (`TIMESTAMPTZ`, Default `now()`)
* **RLS Policies for Messages**:
  * `Access validation` $\rightarrow$ Users can view/insert messages where `auth.uid() = student_id`. Admins (`devcom_head` or `officer`) can read all messages.

## 🗄️ 3. Computational Views

### View: `events_with_slots`
To prevent double-booking or overbooking, event capacity is calculated in PostgreSQL:
```sql
CREATE OR REPLACE VIEW public.events_with_slots AS
SELECT 
  e.*,
  COALESCE(count(r.id) FILTER (WHERE r.status != 'cancelled'), 0)::integer AS registered_count,
  COALESCE(e.registration_cap - count(r.id) FILTER (WHERE r.status != 'cancelled'), e.registration_cap)::integer AS slots_left
FROM events e
LEFT JOIN event_registrations r ON e.id = r.event_id
GROUP BY e.id;
```
This guarantees capacity numbers remain transactionally consistent without race conditions.
